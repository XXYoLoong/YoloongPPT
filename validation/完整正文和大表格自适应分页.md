# 完整正文和大表格自适应分页

## 基线、范围和当前证据状态

已读取原始工作簿中的 DEC-014–021、TPL-007/011/012、对应任务与 AC-014/015。AC-014 要求大表格/多列超容量时采用拆页或表格方案，不能缩至不可读；AC-015 要求超长中英混合标题与列表触发 ContentBudget/AdaptiveLayout 且无溢出。用户要求完整正文、全部表格单元格与原数字/单位保留，因此本实现只采用可追溯的可见分页，不能截字、丢单元格或把核心正文移入备注。

当前状态：Docker 恢复后已实际执行唯一验证驱动，161 项组件检查通过；三个常规组和一个硬页数可容纳边界组共生成 20 页真实可编辑 PPTX、4 份 PDF 和 20 份逐页 PNG，四组 deterministic QA 均 P0=0 且无警告。另对已保存的 PDF 按原生表格单元格边界核对全部表头、重复关键列与数据文字，228 项实物单元格检查通过，没有重新生成或调用模型。白名单制品位于 [adaptive-content-artifacts](adaptive-content-artifacts/)，原两次失败单独保留。

完整 308 条需求、453 个任务、全链路和原验收仍保留。此次组件接入不表示 DEC-014–021、三个上游模板路线或 AC-014/015 原完整验收已完成。

## 实际消费入口

- `narrative.prepare(task,sources,context,schemas,artifacts)` 从 DEC-002 归一化约束保留页数来源。`constraints.hard` 中的精确页数保持 hard；实际应用的软偏好保持 soft；其余为 default。模型仍首先规划原目标页数。
- `narrative.finalize(proposal,narrative_context,sources,schemas=None,artifacts=None,adaptive_policy=None,templates=None)` 校验来源和假设引用，然后调用 `adaptive_content.adapt`。旧断点上下文缺少新策略时仍按原精确页数处理，不重新解释为软预算。
- 当前主链路顺序为 `visual.finalize → narrative.finalize → compile_deck`，视觉资产先完成实际解析；适配续页再进入原生槽位与原子执行。
- `adaptive_content.adapt(proposal,policy=None,templates=None,schemas=None,artifacts=None)` 返回新 proposal 和 report，不污染原 proposal，不调用模型或安装依赖。report 写入 `adaptive-content-result.json`，同时进入叙事 `section_budget.adaptive_content` 和 DEC-014 trace。
- `adaptive_layout.fit_elements(content,elements,page_style,templates=None)` 在候选旧容量检查之前调用，返回元素、样式及几何 trace。主智能体已将其接到共享 layouts。文字、字号和已有槽位键保持，溢出的全宽标题增加高度并重新分配下方区域；不合适的窄标题候选明确拒绝。

## 页预算与显式重复关键列

完整适配策略为：

```json
{
  "page_budget": {"kind": "soft", "target": 2, "minimum": 1, "maximum": 30},
  "table_key_columns": {"1": [0]},
  "assumption_markers": {}
}
```

`table_key_columns` 的键为原始页的零基索引，值为该原表的明确关键列索引。运行入口通过原任务 `runtime_preferences.adaptive_policy.table_key_columns` 和 DEC-002 归一化值传递。横向容量不足且没有明确关键列时返回 `ADAPTIVE_TABLE_KEY_COLUMNS_REQUIRED`，不会猜测首列的业务含义。

hard 的最小/最大页数必须等于原目标；完整可读内容需要更多页时返回 `ADAPTIVE_PAGE_BUDGET_EXCEEDED`。外部传入策略不能改变已归一化的硬页数、目标或来源。soft/default 允许在明确的 1–30 页预算内增加页数，报告目标、实际页数、偏差与原因；不会增加空页凑数。

表格 writer 当前不直接显示 `table.units`，本模块将原单位字符串显式放入每个 table 续页正文，并登记来源为 `table.units`。它不被混入原正文字符偏移记录，便于核对追加展示与原输入的区别。

## 可消费契约

- `contracts/adaptive-content-policy.schema.json`：原硬/软/默认预算、明确关键列与原可见标记。
- `contracts/adaptive-content-result.schema.json`：实际页数、原正文偏移、原表行列坐标、原视觉/表格哈希及保存断言。
- `contracts/adaptive-layout-result.schema.json`：实际几何变更与容量测量，不声称语义或渲染验收。

前两份由 `adapt` 运行时直接校验。第三份由唯一验证驱动校验真实 `fit_elements` 输出；主链路保存该输出到版式 trace。

### 真实失败与修复

1. `20261011-102331` 的首次实物验证在 2 项检查后失败：单个段落本身可容纳，但必需的可见假设标记未参与分句前的容量预留。修复后按正文片段加必须可见标记/单位共同测量，没有删正文或隐藏标记。证据：[initial-marker-capacity-failure](adaptive-content-artifacts/initial-marker-capacity-failure/)。
2. `20261011-102358` 旧行高版本完成长正文实物，但长标题 PDF 最后一行超出标题框并邻近正文。实际 Noto 32pt/Pillow 42px 的 ascent/descent 为 49+13px，旧 `1.25 × point × 4/3` 每行约 53.33px 低估。主智能体与本模块统一采用 `line_box=max(旧估算, ascent+descent)`，分别记录首行与后续 advance 的保守上界；适配另留一次总高度 0.04in 的舍入/基线余量。16pt 页脚仍可容纳原 0.38in，不降低字号。证据：[historical-font-line-height-failure](adaptive-content-artifacts/historical-font-line-height-failure/)。
3. 新字体 metrics 改变了正文分页，因此没有复用旧成功正文制品；`20261011-102753` 为新测量版本重新生成并实际渲染的 20 页成功制品。成功组源码的 8 项哈希、89 项实际使用契约哈希在导出时与当前文件匹配，源码文件修改时间均早于该成功运行开始。

[export-manifest.json](adaptive-content-artifacts/export-manifest.json) 登记 159 项白名单制品（另有 manifest 自身）、每个文件的字节数与 SHA-256。失败与成功分组各自保留，没有覆盖旧现场。没有模型调用、应用重启、新依赖安装、原工作簿修改或子智能体 Git 操作。

这些检查属于人工批准字面夹具的产品组件集成与实物证据。独立事实/视觉模型复审、全部语义拆合、锁定模板槽位、三上游模板和完整 AC-014/015 仍待按原基线验证，不能据此宣称完整 AI PPT 系统交付。
